Why jurl

It can rank badly.
It can't make things up.

jurl doesn't use a chatbot. It uses decision models: Jev reads the text and Clef looks at the images. Neither writes a word. They only say how likely each paragraph, link or image is to be what you want, and jurl prints the winners exactly as they appear on the page. No summary that drifts, no URL that doesn't exist.

It's fast.

Most pages take under a second, end to end.

jurl <url> · 0.6–1 s

It's cheap.

About a thousand pages per dollar of API usage.

jurl <url> · $0.0004–0.0013

Recipes

Plain text out. Pipes in.

Everything prints plain text or plain URLs, so jurl fits in a pipe — or in an agent's toolbox.

Read the top 3 Hacker News stories, one key paragraph each

jurl -l -n 3 news.ycombinator.com | xargs -n1 jurl -n 1

Download the photo that matches

jurl -f "a bridge over a river" en.wikipedia.org/wiki/Cologne | xargs curl -sO

Every chart in a post

jurl -f "a chart or graph" -n 10 blog.cloudflare.com/markdown-for-agents/ | xargs -n1 curl -sO

Only the confident answers, for scripts

jurl --json -q "installation" github.com/BurntSushi/ripgrep | jq -r '.blocks[] | select(.p > 0.8) | .text'

jurl example.com jurl reads pages with Jev, TypeSafe's decision model. It needs your API key, once. Get one at https://console.typesafe.ai TypeSafe API key (hidden): Checking… ok. Saved to ~/.config/jurl/env

The first run asks for a TypeSafe API key, checks it and saves it. For --vision and --find, run jurl init and add a Cloudflare Workers AI token.

Your keys, your data

No server. No account.

jurl talks to the model APIs directly, with your keys.

Who you pay

TypeSafe for Jev ($0.042 per million input tokens) and Cloudflare for Clef-flash ($0.09 per million). Output is free on both.

What leaves your machine

The text of the page goes to TypeSafe. With --vision or --find, the images go to Cloudflare too. Keep that in mind for internal pages.

What jurl can't read

It sends no cookies, so pages behind a login are out of reach.

How it works

One yes-or-no question per candidate.

01 · FETCHSplit the page

jurl asks for markdown first. Otherwise its own extractor drops navigation, footers and scripts, and splits the rest into blocks, links and images. Empty JavaScript app? It renders it in Lightpanda.

02 · ASKTwo judges, at once

Jev reads text"is block 12 the point?"
p = 0.97
Clef looks at images"does this show a cathedral?"
p = 0.96

Every question goes to Jev in a single request, so asking 100 takes about as long as asking one. Clef looks at the pixels while Jev reads, not after.

03 · PRINTKeep the winners

What clears the threshold, in page order. A heading comes back only when something in its section does. Verbatim, always.

Models choose, they don't write. That's why the output is safe to pipe into xargs curl.
